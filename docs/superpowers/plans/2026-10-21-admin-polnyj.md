# Админка: полный функционал — план

Дата: 21.10.2026, вечер перед показом. Исходные требования: `docs/01`, `docs/02`,
`docs/03`; ограничения: `CLAUDE.md`; ловушка: `docs/06`, сцена 2.

Один пункт — один коммит, тесты зелёные, без пуша.

## Решения, которые надо согласовать

1. **Черновик хранится в самом занятии.** Поля занятия — рабочая копия админа.
   `published: false` значит «есть неопубликованные правки». `pub` — снимок
   последней опубликованной версии (или нет, если занятие новое). `deleted: true` —
   удалено в черновике. Студент видит `published ? lesson : lesson.pub`.
   Ловушка (`L15`: `published: false`, без `pub`) под эту схему подходит без изменений.
2. **Изменения на дату применяются сразу, без публикации.** Замена «сегодня, больничный»
   не может ждать кнопки. Черновик и публикация касаются только занятий (сетки семестра).
   Так написано и в `docs/02`: Change — «поверх опубликованного расписания».
3. **Замена аудитории в один тап меняет аудиторию занятия на всех датах**, а не только
   на 21.10. Конфликт недельный: ставить исключение на одну среду значит оставить его
   на остальных. Проверено на сиде: 212, 234, 346 и 143 свободны во все среды семестра,
   то есть список в сцене 2 не меняется. Если аудитория конфликтует на какой-то другой
   дате, она в список не попадает.
4. **«Опубликовать» не пускает, пока в черновиках есть ошибки-конфликты.** Пишет, какие
   занятия мешают. Предупреждения не мешают. Ловушку случайно не опубликовать.
5. **Отмена на тосте — честная.** Возвращает занятие в состояние «до» и пишет в журнал
   запись «отменил правку». Журнал не переписывается задним числом.
6. **Экспорт: сначала CSV, потом настоящий .xlsx.** .xlsx стоит делать: в нём
   объединённые ячейки для потоков и вид как у файла учебной части. CSV этого не
   передаёт, а на показе спросят «а в Excel?». Делается без npm: zip без сжатия
   (метод STORE) + CRC32 + минимальный SpreadsheetML, ~150 строк чистого кода в
   `src/domain/export-xlsx.js` с тестами. Делаю **последним**, только если 1–5 готовы
   и проверены. Если времени не хватит, остаётся CSV (BOM + `;`).

## Попутно найденный баг (чиню в пункте 1)

`renderGrid` и `renderAudit` при каждой отрисовке вешают ещё один `click` на
постоянный `#view`. После трёх переходов клик срабатывает трижды. Пока сетка только
на просмотр, это лишние перерисовки. С записью это будут двойные правки.
Перевожу на один обработчик (`AbortController`).

## Устройство

- `src/data/session.js` — состояние, `ensure`, `commit`, `ctx`. Нужен, чтобы разрезать
  `api.js` (363 строки) без глобального состояния снаружи слоя данных.
- `src/data/api.js` — чтение, как сейчас, плюс `export * from './api-admin.js'`.
  Единственная точка входа для экранов остаётся одна.
- `src/data/api-admin.js` — запись: `saveLesson`, `deleteLesson`, `checkLessonDraft`,
  `saveChange`, `deleteChange`, `checkChange`, `publish`, `revert`, `exportWeek`.
  Каждая запись проверяет зону администратора и версию (оптимистичная блокировка:
  «Запись изменили, пока вы редактировали»), пишет журнал с `before`/`after`.
- `src/domain/` (TDD):
  - `drafts.js` — `publishedView(lessons)`, `editLesson(lesson, patch)`,
    `deleteDraft`, `publishLessons`, `pendingOf(lessons)`. Чистые функции над массивом.
  - `audit-diff.js` — `lessonDiff(before, after)` → `[{field, from, to}]`.
  - `dates.js` + `parseDayList('07.09, 21.09', term)` → ISO-даты.
  - `conflicts.js` + `checkChange(change, occurrences, ctx)`.
  - `export-csv.js`, затем `export-xlsx.js` (zip STORE + CRC32).
- `src/views/admin/`:
  - `conflict-sheet.js` → карточка занятия: тап по свободной аудитории, кнопки
    «Изменить», «Изменение на дату», «Удалить». В чужой зоне кнопок нет.
  - `lesson-form.js` + `date-rule-field.js` + `check-panel.js` — форма занятия.
  - `change-form.js` — изменение на дату.
  - `publish.js` — вкладка «Публикация»: счётчик, список правок, «Опубликовать», экспорт.

## Пункты

### 1. Аудитория в один тап (коммит 1)
- Тест: на сиде замена `L15` → `r-212` убирает конфликт аудитории, у занятия
  остаётся `published: false`, в журнале запись с `roomId: r-133 → r-212`.
- Тест: `revert` возвращает `r-133` и конфликт.
- Тест: список свободных для ловушки — ровно `212, 234, 346, 143`.
- UI: чипы аудиторий становятся кнопками ≥44px. Тап → сохранить → шторка закрыта,
  сетка перерисована, тост «Ауд. 212 — конфликт снят» + «Отменить».
- Фикс обработчиков `click`.

### 2. Форма занятия (коммит 2, может разбиться на 2a/2b)
- Домен: `parseDayList`, `editLesson`, `deleteDraft`, валидация обязательных полей.
- Поля: дисциплина, вид, группы (чипы, несколько = поток), подгруппа, преподаватель,
  аудитория/онлайн, день, пара (из сетки звонков подразделения на этот день), правило
  дат: «Каждую неделю / Через неделю / Отдельные даты», диапазоны с «+ ещё диапазон»,
  исключения, мини-календарь семестра.
- Живая проверка с задержкой 150 мс: «Конфликтов нет» или список + свободные аудитории
  в один тап. Ошибка блокирует «Сохранить», предупреждение — галочка «Понимаю».
- Входы: «+ Занятие» в шапке сетки; тап по пустой ячейке (день, пара, группа, подгруппа
  уже заполнены); «Изменить» в карточке. «Удалить» с подтверждением и «Отменить».
- Чужое подразделение: пустые ячейки не кликаются, кнопок правки нет, api отказывает.

### 3. Изменение на дату (коммит 3)
- Домен: `checkChange` — накладывает кандидата на вхождения и ищет конфликты
  (перенос на занятое время → ошибка, случай 10 из `docs/02`).
- Форма из карточки ячейки: «Отменить / Заменить преподавателя / Сменить аудиторию /
  Перенести», причина, та же проверка. Существующие изменения можно снять.
- Проверка: студент видит изменение на «Сегодня», «Неделе», «Изменениях».

### 4. Черновик → публикация (коммит 4)
- Домен: `publishedView`, `publishLessons`, `pendingOf`.
- Студенческие запросы читают `publishedView`. Тест: правка опубликованного занятия
  не видна студенту до публикации, видна после.
- Вкладка «Публикация»: счётчик, список правок (новое / изменено / удалено, было → стало),
  блок «сначала решите конфликты», «Опубликовать». Версия семестра +1, `publishedAt`.

### 5. Журнал (коммит 5)
- Все записи из пунктов 1–4 уже пишут журнал. Здесь — экран: «было → стало» по полям,
  фильтр по группе и администратору.

### 6. Экспорт (коммит 6, затем 7)
- CSV недели группы. Кнопка на вкладке «Публикация».
- .xlsx — если хватает времени.

## Что сознательно не делаю

- Несколько преподавателей в одном занятии в форме: модель поддерживает,
  в форме один (плюс замена на дату). Сид с двумя преподавателями отображается.
- «+ новая дисциплина» в форме, «Действует с …» для версии, дополнительное занятие
  (`extra`) из формы, отдельная вкладка «Изменения» у админа. Всё это дёшево добавить
  после показа, на сценарий не влияет.
