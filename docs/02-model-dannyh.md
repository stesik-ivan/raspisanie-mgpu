# Модель данных

Модель выведена из двух реальных образцов в `samples/`. В демо данные хранятся как JSON в `localStorage`, после одобрения те же сущности станут коллекциями PocketBase.

## Что показали образцы

**ВО, ИЕСТ, 1 курс** (`samples/VO_IEST_1kurs_1sem_2026-27.xlsx`)
- Шапка: институт, курс, уровень и форма, направления с профилями, адрес корпуса, период семестра, «УТВЕРЖДАЮ».
- Пары по 80 минут: 09.00–10.20, 10.30–11.50, 12.40–14.00, 14.10–15.30, 15.40–17.00. Суббота в сетке есть.
- Каждая группа занимает **две колонки — это подгруппы**. Объединённые ячейки означают общее занятие на поток из нескольких групп, таких в файле 141.
- **Чётной и нечётной недели нет. Даты указаны явно:**
  - разовые: `07.09, 21.09`;
  - через неделю: `10.09, 24.09, 08.10, 22.10`;
  - каждую неделю: `с 08.09 по 29.12`;
  - с разрывом: `с 09.09 по 28.10; с 11.11 по 23.12`;
  - открытый конец: `с 09.09`.
- В одной ячейке бывает 2–3 занятия: `Картография (лк) 02.09 (лб) с 09.09 … ауд.304\\к.кл 307` — лекция и лабораторная с разными датами и аудиториями.
- Виды: `лк`, `пр`, `лб`. Должности: `доц.`, `ст.преп.`, `асс.`. Аудитории записаны вразнобой: `ауд.304`, `к.кл 307`, `к\кл.307`.

**СПО, 11СПш-261** (`samples/SPO_11SPsh-261_s22.09.2026.pdf`, скан)
- Уроки по 45 минут, до 10 в день: 09:00–09:45, 09:50–10:35 … 17:15–18:00. **В субботу своя сетка** (12:35–13:20 и т. д.).
- Расписание «с 22.09.2026», то есть у него есть версии с датой начала действия.
- Подгруппы через `/`: `Еленская Я.А. / Ульянова Е.Ш. … ауд. 103/106`.
- Корпуса Ч1 и Ч3 с расшифровкой адресов. Бывают залы (`зал Б-123/Б-124`) и онлайн (`Учебное пространство Сферум`).
- Внеурочное занятие «Разговоры о важном».
- Это скан, автоматически не читается. Для импорта нужен исходный Excel.

**Общий корпус Ч-1** используется и ВО, и СПО с разными сетками звонков. Поэтому конфликты считаются по времени, а не по номеру пары.

## Сущности

```ts
Unit        { id, name, short, kind: 'vo'|'spo', bellScheduleId, adminIds[] }
Program     { id, unitId, code, name, level: 'bak'|'mag'|'spo', form: 'och'|'zaoch'|'och-zaoch' }
Group       { id, programId, code /* 'ГШТ-261' */, course, subgroups: string[] /* [] | ['1','2'] */ }
Building    { id, code /* 'Ч-1' */, address }
Room        { id, buildingId|null, name /* '304' */, kind: 'aud'|'comp'|'lab'|'gym'|'online', capacity? }
Teacher     { id, fio /* 'Иванова А.Б.' */, position /* 'доц.' */, unitIds[] }
Discipline  { id, unitId, name }
BellSchedule{ id, name, slots: {n, start:'HH:MM', end:'HH:MM'}[], byWeekday?: { [1..7]: Slot[] } }
Term        { id, unitId, name /* '1 семестр 2026/27' */, from, to,
              status: 'draft'|'published', version, validFrom, publishedAt? }

Lesson {                       // одна «клетка» расписания
  id, termId, disciplineId,
  kind: 'лк'|'пр'|'лб'|'урок'|'внеуроч'|'конс'|'экз'|'зач',
  groupIds: string[],          // 1 группа или поток
  subgroup: string|null,       // null = вся группа
  teacherIds: string[],        // несколько = подгруппы/совместное ведение
  roomId: string|null,         // онлайн — Room с kind 'online'
  weekday: 1..7, slot: number, // номер пары по BellSchedule подразделения
  dateRule: DateRule,          // как ввёл человек — для отображения и правки
  dates: string[],             // ISO-даты, развёрнутые из dateRule, — истина для всех расчётов
  updatedAt, version           // оптимистичная блокировка
}

DateRule = {
  parts: (
    | { type: 'dates', list: string[] }                       // 07.09, 21.09
    | { type: 'range', from, to|null, everyWeeks: 1|2 }       // с 08.09 по 29.12; через неделю
  )[],
  except: string[]                                           // праздники, переносы
}

Change {                       // изменение поверх опубликованного расписания на дату
  id, date, lessonId|null,
  type: 'cancel'|'teacher'|'room'|'move'|'extra',
  patch: { teacherIds?, roomId?, date?, slot?, … },  // для 'extra' — полное занятие
  reason, adminId, createdAt
}

AuditEntry { id, at, adminId, entity, entityId, action: 'create'|'update'|'delete'|'publish', before, after }
Admin      { id, fio, unitIds[] }  // зона ответственности
```

## Вхождение занятия

Для каждого `Lesson` и каждой даты из `dates` строим **вхождение**:
`{ lessonId, date, start, end, groupIds, subgroup, teacherIds, roomId }`.
Время `start/end` берём из сетки звонков подразделения первой группы, с учётом `byWeekday`. Потом поверх накладываем `Change` за эту дату: отмена убирает вхождение, перенос двигает, замена меняет поля, `extra` добавляет новое.

Все экраны и все проверки работают с вхождениями.

## Конфликты

Два вхождения конфликтуют, если у них одна `date`, пересекаются интервалы `[start, end)` и выполняется хотя бы одно из условий:

| Тип | Условие | Уровень |
|---|---|---|
| Аудитория | одинаковый `roomId`, и это не онлайн | ошибка |
| Преподаватель | пересекаются `teacherIds` | ошибка |
| Группа | пересекаются `groupIds`, и подгруппы пересекаются (`null` пересекается со всеми, `'1'` и `'2'` — нет) | ошибка |
| Переезд | у группы или преподавателя занятия подряд в разных корпусах с перерывом **20 минут или меньше** | предупреждение |
| Вместимость | суммарная численность групп больше `capacity` | предупреждение |

Ошибка блокирует сохранение. Предупреждение можно подтвердить. Форма показывает конфликт текстом: «Ауд. 304 (Ч-1) 14.10 в 10:30–11:50 занята: ГА-251, Геология (лк)». Рядом — свободные аудитории того же типа в том же корпусе на это время.

Если двое админов правят одно занятие одновременно, второй получает «Запись изменили, пока вы редактировали» и видит актуальную версию. Тихой перезаписи нет.

## Тестовые случаи для `domain/` (писать до кода)

1. `с 09.09 по 28.10; с 11.11 по 23.12` по средам → 15 дат, без 04.11.
2. `10.09, 24.09, 08.10, 22.10` → ровно эти 4 даты.
3. `range` с `everyWeeks: 2` и `except` с праздником.
4. Пара ВО 10:30–11:50 и урок СПО 10:40–11:25 в одной аудитории Ч-1 → конфликт аудитории.
5. Пара ВО 09:00–10:20 и урок СПО 10:40–11:25 в той же аудитории → нет конфликта.
6. Поток ГШТ-261+ГОБЩ-261 (вся группа) и лаба ГОБЩ-261 подгр. 2 в то же время → конфликт группы.
7. Лабы ГШТ-261 подгр. 1 и подгр. 2 в одно время в разных аудиториях → нет конфликта.
8. Онлайн-занятие у двух групп одновременно с разными преподавателями → нет конфликта аудитории.
9. Преподаватель в Ч-1 до 12:30, следующий урок в Ч-3 в 12:50 → предупреждение о переезде. Это ровно 20 минут, и порог поэтому включающий: 20 минут — настоящее окно сетки СПО между 4-м и 5-м уроком, при строгом «меньше 20» система прозевала бы самый частый реальный переезд.
10. Отмена на дату убирает вхождение. Перенос на другую дату создаёт конфликт, если там занято.
11. Суббота СПО берёт `byWeekday[6]`, а не основную сетку.

## Опубликованное представление (для студентов)

В боевой версии сервер при каждой публикации или изменении пересобирает:
- `pub/groups/<groupId>.json` — вхождения на семестр с наложенными изменениями;
- `pub/teachers/<teacherId>.json`;
- `pub/groups/<groupId>.ics`, `pub/teachers/<teacherId>.ics`;
- `pub/index.json` — дерево подразделений, групп и преподавателей для поиска.

Студенческий интерфейс читает **только** эти файлы. В демо `api.js` отдаёт ту же форму из памяти.
